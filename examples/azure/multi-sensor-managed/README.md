# Multi-Sensor Managed Example

Deploys multiple Corelight single-instance sensors behind an internal load balancer, each auto-paired with an external Fleet Manager instance.

## Architecture

- **N sensors** deployed as individual VMs (no scale set) via `modules/azure/sensor-single`
- **Internal load balancer** distributes mirrored VXLAN traffic (UDP 4789) across all sensors
- **Shared NSGs** for management and monitoring (one pair for all sensors)
- **Fleet pairing** via per-sensor tokens generated by the registration script

## Prerequisites

- An existing VNet in Azure
- A Corelight sensor VM image (use `scripts/azure/copy-azure-image.sh`)
- A running Fleet Manager instance
- `jq` and `curl` installed (for the registration script)

## Usage

### 1. Register sensors with Fleet

The registration script calls the Fleet API to create catalog entries and writes pairing tokens to `sensors.json`. Existing entries are never modified — tokens are stable across runs.

```bash
./scripts/register-sensors.sh \
  --fleet-url https://fleet.example.com:1443 \
  --username admin \
  --password 'secret' \
  --sensors sensor-1,sensor-2,sensor-3
```

### 2. Configure Terraform variables

```bash
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars with your values
```

### 3. Deploy

```bash
terraform init
terraform plan
terraform apply
```

### 4. Point mirrored traffic to the ILB

The `load_balancer_frontend_ip` output gives the ILB's private IP. Configure your VNet tap, NSG flow logs, or traffic mirroring to send VXLAN-encapsulated packets to this address on UDP 4789.

## Scaling up

To add sensors to an existing deployment:

1. Re-run the registration script with the full list (includes new names):
   ```bash
   ./scripts/register-sensors.sh \
     --fleet-url https://fleet.example.com:1443 \
     --username admin \
     --password 'secret' \
     --sensors sensor-1,sensor-2,sensor-3,sensor-4,sensor-5
   ```
   Only `sensor-4` and `sensor-5` get new tokens. Existing sensors are untouched.

2. Run `terraform apply` — new VMs are created, existing ones are unchanged.

## Upgrading sensor software

To upgrade sensors from one version to another (e.g., 29.2 → 29.3):

1. Update `corelight_sensor_image_id` in `terraform.tfvars` to the new image
2. Run `terraform apply` — VMs are recreated with the new image

The pairing tokens in `sensors.json` do not change, so each sensor reconnects to Fleet with the same identity.

## Inputs

| Name | Description | Required |
|------|-------------|----------|
| `location` | Azure region | yes |
| `resource_group_name` | Resource group name (created by this example) | yes |
| `virtual_network_name` | Existing VNet name | yes |
| `virtual_network_resource_group` | Resource group of the existing VNet | yes |
| `management_subnet_cidr` | CIDR for management subnet | yes |
| `monitoring_subnet_cidr` | CIDR for monitoring subnet | yes |
| `corelight_sensor_image_id` | Sensor VM image resource ID | yes |
| `sensor_ssh_public_key` | SSH public key for VMs | yes |
| `fleet_url` | Fleet Manager URL | yes |
| `fleet_server_sslname` | TLS hostname for Fleet certificate verification | no (default: `1.broala.fleet.product.corelight.io`) |
| `community_string` | Sensor API password | yes |

## Outputs

| Name | Description |
|------|-------------|
| `sensor_private_ips` | Map of sensor name → management private IP |
| `sensor_vm_ids` | Map of sensor name → VM resource ID |
| `load_balancer_frontend_ip` | ILB frontend IP for mirrored traffic |
